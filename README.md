<summary id="page-i--about-me"><strong>Page I — About me</strong></summary>
<br />

I'm a Computer Science student at the **University of the Philippines Cebu**. I learn best by building complete projects: working through the data model, interface, failure cases, documentation, and the less glamorous parts needed to make something usable.

My repositories range from a Godot tower-defense game to browser-based physics and mapping tools. The subjects change, but I usually come back to the same priorities: keep data on the user's device when possible, explain what the software is doing, and make the main workflow easy to understand.

I mainly work with **TypeScript and JavaScript, Python, C++, GDScript, and SQL**. I'm especially interested in mobile engineering, data visualization, simulation, automation, and small tools that solve a specific problem well.

</details>

<summary id="page-iii--tools-and-approach"><strong>Page III — Tools and approach</strong></summary>
<br />

**Languages:** TypeScript, JavaScript, Python, C++, GDScript, and SQL<br />
**Applications:** React, React Native, Expo, Node.js, and Streamlit<br />
**Games and simulations:** Godot, GDExtension, numerical models, and interactive visualization<br />
**Data work:** CSV and JSON pipelines, GeoJSON, validation, mapping, and export workflows

I prefer small, understandable systems over stacks chosen for appearance. I use browser and platform features before adding dependencies, keep irreversible actions behind clear confirmation, and document the limits of prototypes instead of presenting them as finished products. For me, a useful repository should be possible to run, inspect, and learn from—not just look complete in a screenshot.

</details>
